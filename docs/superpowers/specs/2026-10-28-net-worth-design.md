# Капитал и его динамика (net worth)

## Зачем

Учёт денег в приложении закончен: транзакции, категории, импорт выписок,
синхронизация банков и кошельков. Пользователь пользуется приложением для учёта
капитала (wealth management), а не для бюджета. Его главный вопрос: «сколько у
меня всего и как это меняется». Сейчас на него нет ответа. Балансы считаются
только на сегодня. Акции и ETF у брокера, недвижимость, вклады и облигации не
учитываются вовсе.

Аналоги (Kubera, Ghostfolio, Finary, Getquin, Sharesight, Wealthfolio) строятся
вокруг одного экрана: итог капитала, его график во времени и состав. Полный
обзор функций лежит в `intent.md`.

**Успех:** пользователь раз в месяц открывает страницу «Капитал», вписывает
стоимость брокерского счёта из кабинета брокера и видит:

- итог в своей валюте (`users.currency`);
- график по месяцам за всю историю;
- из чего состоит капитал;
- на счетах с оценкой — сколько он вложил и сколько это стоит сейчас.

## Цели

- Страница «Капитал»:
  - текущий итог;
  - помесячный график за всю историю;
  - разбивка по видам активов и по валютам.
- Новые виды счетов, стоимость которых задаётся ручной оценкой: брокерский
  (`investment`), недвижимость (`property`), вклад или облигации (`deposit`).
- Простая доходность счёта с оценкой: «вложено» против «стоит», в деньгах и в %.
- Каждый пользователь сам выбирает, какие из видимых ему счетов входят в его
  капитал.

## Не-цели

- Позиции по тикерам, котировки, XIRR/TWR, дивиденды, налоговые отчёты.
  Возможная следующая фаза поверх брокерского счёта. Пользователь сознательно
  выбрал ручной ввод итоговой стоимости.
- Долги: кредиты, ипотека.
- Прогнозы, FIRE, целевое распределение, «наследник».
- Снимки капитала по расписанию: история считается на лету (см. «История»).

## Анти-цели (провал, даже если всё формально работает)

- Список счетов и страница «Капитал» показывают для одного счёта разные суммы.
- Курс становится хранимыми данными транзакции. Это нарушает принцип из
  CLAUDE.md: курс хранится только в кэше `exchange_rates`.
- После перевода денег на брокерский счёт капитал на графике проседает до
  следующей оценки.
- Чужой выбор счетов влияет на мой капитал.

## Модель данных

### Виды счетов

Миграция `019`: в `chk_accounts_type` добавляются `investment`, `property` и
`deposit`. Поведение этих счетов в остальном не меняется:

- на них бывают транзакции, переводы, `start_balance`;
- общий доступ работает как обычно;
- пополнение брокера и покупка квартиры — это перевод с банковского счёта;
- проценты по вкладу можно провести как доход, а можно просто учесть в
  следующей оценке.

Привязка к банку (только для `bank`) и отслеживание блокчейна (только для
`crypto`) на новые типы не распространяются.

### Оценки

```sql
account_valuations (
  id SERIAL PRIMARY KEY,
  account_id INTEGER NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  as_of DATE NOT NULL,
  value INTEGER NOT NULL,       -- в масштабе счёта (accounts.scale), может быть 0
  user_id INTEGER NOT NULL REFERENCES users(id),  -- кто ввёл
  created_at TIMESTAMPTZ DEFAULT now(),
  UNIQUE (account_id, as_of)
)
```

- Оценку можно поставить на счёт любого типа. В интерфейсе это предлагается
  только для `investment`, `property` и `deposit`.
- Права: читать оценки может уровень READ (1). Создавать, менять и удалять —
  уровень WRITE (2).
- API: `GET/POST /api/accounts/:id/valuations`, `PUT/DELETE
  /api/accounts/:id/valuations/:valuationId`. Суммы, как везде, передаются
  десятичными и переводятся через `toCents`/`toDecimal`.
- При повторной оценке на ту же дату:
  - `POST` отвечает 409;
  - правка — через `PUT`.
- Оценка на будущую дату — 400.

### Стоимость счёта на дату D

- **Транзакционный баланс** = `start_balance` + все транзакции счёта до D
  включительно. Так баланс считается сейчас в `withBalances`.
- **С какой даты считается `start_balance`.** С даты первой транзакции счёта.
  У счёта без транзакций — с `accounts.created_at`. До этой даты счёт даёт 0.
  Первая точка графика — самая ранняя из таких дат и дат оценок.
- **«Сегодня» — по UTC**, как в bank sync. В `balance` и `invested` входят все
  транзакции, в том числе с будущей датой, как сейчас. Точка «сегодня» на
  графике и итог страницы считаются так же, поэтому совпадают со списком
  счетов. Отсечка по дате D применяется только к прошлым месяцам.
- **Стоимость:**
  - без оценок на дату ≤ D стоимость равна транзакционному балансу;
  - с оценкой: берётся последняя оценка V на дату A ≤ D, и стоимость =
    V + чистый поток транзакций счёта в датах (A, D].
- Транзакции в сам день оценки считаются уже вошедшими в неё.
- Так перевод на брокерский счёт после оценки сразу увеличивает стоимость, и
  график не проседает.
- **Вложено** = транзакционный баланс на D.
- **Доходность** = стоимость − вложено.
- **%** = доходность / вложено. Если вложено ≤ 0, процент равен `null`.

Оценка заменяет транзакционный баланс не только на странице «Капитал».

- `balance` в ответах `/api/accounts` становится стоимостью на сегодня, и
  `user_balance` считается от неё.
- Добавляются поля:
  - `invested` — транзакционный баланс (в валюте счёта);
  - `last_valuation_date` — `null`, если оценок нет.
- Для счетов без оценок `balance` и `invested` совпадают, поэтому поведение не
  меняется.
- Удаление счёта по ненулевому балансу проверяет транзакционный баланс, как
  сейчас.
- Стоимость считает одна функция в сервисе. Её используют и accounts, и
  net-worth.

### Выбор счетов для капитала

```sql
account_user_settings (
  account_id INTEGER NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  in_net_worth BOOLEAN NOT NULL,
  PRIMARY KEY (account_id, user_id)
)
```

- Это личная настройка. Менять её может пользователь с любым уровнем доступа к
  счёту, и выбор не влияет на других участников.
- Если строки нет, действует значение по умолчанию:
  - **включён** для своего или совместного счёта (уровень 3–4);
  - **выключен** для счёта, открытого на чтение или запись (уровень 1–2).
- Строка удаляется в той же транзакции, в которой пользователь теряет доступ
  (`accountShares.removeMember`, как ссылки на банк).
- Выбор действует на всю историю. Включённый счёт попадает во все прошлые
  месяцы, а не только с даты включения.
- Удалённые (`deleted = true`) счета не входят в сегодняшний итог и в список
  счетов на странице. В историю они входят по общему правилу выбора. Счёт
  удаляется только с нулевым балансом, поэтому после закрытия он даёт 0, а до
  закрытия даёт свой настоящий баланс. Иначе перевод с закрытого счёта
  выглядел бы как новые деньги.
- API:
  - `in_net_worth` возвращается в ответах `/api/accounts` (с учётом значения по
    умолчанию);
  - меняется через `PUT /api/accounts/:id/net-worth` с телом `{ include:
    boolean }`;
  - эндпоинт отдельный, потому что `PUT /api/accounts/:id` требует ADMIN.

## История и курсы

- Точки графика — конец каждого месяца, от самой ранней транзакции или оценки
  среди выбранных счетов. Последняя точка — сегодня.
- История считается на лету: стоимость каждого счёта на дату, пересчитанная в
  `users.currency` по курсу на эту дату.
- Снимков нет, поэтому выбор счетов и правка старых транзакций сразу
  отражаются на всей истории.
- **Исторические курсы.** `services/currency.ts` получает курс на дату и
  кэширует его в `exchange_rates`:
  - по `as_of` (уникальный ключ `(from, to, as_of)` уже есть);
  - Frankfurter (`/{date}` или time series), иначе CoinGecko history.
- Курс на прошлую дату не меняется, поэтому однажды полученный курс из кэша
  больше не обновляется.
- Бесплатный CoinGecko отдаёт историю примерно за 365 дней. Если курса на дату
  нет ни у провайдера, ни в кэше:
  - берётся ближайший по дате курс из кэша;
  - точка помечается `approximate: true`.
- Если курса для валюты нет вообще, счёт не входит в точку, и она тоже
  помечается `approximate`. Так же ведёт себя `user_balance: null` сегодня.

## API капитала

`GET /api/net-worth` (только авторизация). Ответ:

```ts
{
  currency: string,              // users.currency
  total: number | null,          // сегодня, десятичное
  approximate: boolean,
  byType: { type: AccountType, value: number }[],
  byCurrency: { currency: string, value: number }[],  // в users.currency
  accounts: { id, name, type, currency, value, valueUser, invested, gain, gainPct, inNetWorth }[],
  history: { date: string, total: number, byType: Record<AccountType, number>, approximate: boolean }[]
}
```

- `accounts` — все видимые счета, включая невыбранные: в этом списке на
  странице переключают выбор.
- Итоги и `history` считаются только по выбранным.

## Фронтенд

- **Маршрут** `/net-worth`, пункт «Капитал» в шапке. На странице:
  - итог;
  - график: стопка по видам активов или линия итога;
  - разбивки по видам и валютам;
  - таблица счетов с переключателем «в капитале», стоимостью, «вложено» и
    «+X%».
- Приблизительные точки и итог помечаются, например «≈» с подсказкой.
- **Форма счёта:** новые типы в выборе типа.
- **Настройки счёта:**
  - переключатель «Учитывать в капитале»;
  - у счетов `investment`, `property` и `deposit` — раздел «Оценки»: список,
    «Добавить оценку» (дата, по умолчанию сегодня, и сумма), правка, удаление.
- **Список счетов на дашборде** показывает стоимость (`balance`). Для счетов с
  оценкой рядом выводится «+X%».
- **Итог над списком счетов** (`AccountsState.summary`) суммирует только счета
  с `in_net_worth`. Это решение пользователя: одна цифра везде. Сам список
  по-прежнему показывает все видимые счета.

## Решения, принятые без пользователя

- Между оценками стоимость = последняя оценка + переводы после неё.
- Счета чужих пользователей (уровень 1–2) по умолчанию выключены из капитала,
  свои и совместные — включены.
- Для старых крипто-курсов берётся ближайший курс из кэша с пометкой
  «приблизительно».
- Страница вынесена на отдельный маршрут `/net-worth` с пунктом в шапке.
- `balance` в `/api/accounts` становится стоимостью, транзакционный баланс
  переезжает в `invested`.
- Удалённые счета входят в историю, но не в сегодняшний итог и не в список.
- `start_balance` считается с первой транзакции, без них — с `created_at`.
- «Сегодня» — по UTC. Транзакции с будущей датой входят в текущий баланс, как
  сейчас.
